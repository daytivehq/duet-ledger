# 운영·업데이트·복구

[매뉴얼 홈](index.md) · [설치](installation.md)

## 평소 운영

Compose 파일이 있는 폴더에서 실행합니다. 다른 위치에서는 `docker compose -f /설치경로/compose.yaml`을 사용합니다.

```bash
docker compose ps
docker compose logs --tail 100 duet-ledger
docker compose restart duet-ledger
```

컨테이너는 재시작 정책에 따라 서버 부팅 후 다시 시작합니다. Docker 자체도 부팅 시 실행되어야 합니다. `/healthz`는 앱 상태 확인용이며 데이터 백업을 대신하지 않습니다.

## 업데이트

먼저 각 기기의 구름 아이콘에서 전송 대기 기록을 동기화하거나 내보냅니다. 이어서 [변경 기록](https://github.com/daytivehq/duet-ledger/blob/main/CHANGELOG.md)을 읽고 암호화 백업과 백업 비밀번호를 보관합니다. 기존 ZIP 백업은 원래 `master.key`도 보관합니다. [Releases](https://github.com/daytivehq/duet-ledger/releases)에서 대상 버전의 이미지 게시 완료를 확인합니다.

Compose와 같은 폴더의 `.env`에서 버전을 지정합니다. 예를 들어 0.4.0로 업데이트하려면 다음 값을 사용합니다.

```dotenv
DUET_LEDGER_IMAGE=ghcr.io/daytivehq/duet-ledger:0.4.0
```

Docker 관리 화면을 사용한다면 해당 화면의 환경변수 또는 `image` 태그를 바꿉니다. `.env`나 실행 환경에 `DUET_LEDGER_IMAGE`가 있으면 Compose 파일의 기본 이미지보다 우선합니다. 업데이트 시점을 직접 선택하려면 `latest` 대신 정확한 버전을 사용하세요.

```bash
docker compose pull duet-ledger
docker compose up -d
docker compose ps
docker compose logs --tail 100 duet-ledger
```

버전 태그를 고정한 경우 pull만으로 다른 버전으로 바뀌지는 않습니다. 실행 중인 컨테이너는 새 이미지 게시만으로 자동 교체되지 않습니다.

기존 데이터 볼륨·환경변수는 유지합니다. 구조가 자동 변경될 수 있으므로 **이전 이미지로만 바꾸는 것은 안전한 되돌리기가 아닙니다.** 되돌릴 때는 업데이트 전 자료 사본과 호환되는 앱 이미지를 함께 사용하세요.

## 이전 이미지 주소에서 전환

기존 `ghcr.io/goodjinc/duet-ledger`를 사용하는 설치는 새 이미지의 게시와 공개 다운로드를 확인한 뒤 `.env`의 `DUET_LEDGER_IMAGE` 또는 Compose의 `image`를 `ghcr.io/daytivehq/duet-ledger:0.4.0`으로 바꾸고 위 업데이트 명령을 실행합니다. `latest`도 소유자 경로를 바꿔야 합니다. **같은 버전을 유지하려면 해당 버전이 새 경로에도 게시됐는지 먼저 확인하세요.**

저장소 이전만으로 기존 설치의 이미지 주소가 자동 변경되지는 않습니다. 기존 Compose 프로젝트 이름·데이터 볼륨·환경변수·접속 주소는 유지합니다. 자료 초기화나 백업 복원은 필요하지 않습니다. **`docker compose down -v`는 자료 볼륨을 삭제하므로 사용하지 마세요.**

## 0.3.0으로 업데이트할 때

0.2.0에서 업데이트하면 저장 구조는 **8을 유지**하며 시작 잔액을 다시 전환하지 않습니다. 기존 계정·거래·공유 관계·앱 비밀번호를 유지합니다.

0.1.1 이하에서 바로 업데이트하면 이전 버전의 변경도 함께 적용됩니다. 저장 구조가 8로 갱신되고 기존 시작 잔액은 계좌 생성 시각의 수입(양수)·지출(음수)로 전환됩니다. 현재 잔액은 유지하지만 해당 기간의 수입·지출 통계는 달라집니다. 업데이트 전 백업을 보관하고 변경된 통계를 확인하세요.

업데이트 후 앱을 새로고침해 새 화면을 불러옵니다. 오프라인 저장은 기본 켜짐·최근 7일이며 **설정 → 오프라인 내역**에서 바꿉니다. 공용 기기에서는 끄세요. 화면 갱신 문제를 해결하려고 브라우저의 사이트 데이터를 삭제하기 전에는 대기 기록을 먼저 내보내세요. [오프라인 안내](offline.md)

## 다른 Docker 환경으로 이전

같은 Docker 서버에서는 기존 앱을 중지하고 `duet-ledger-data` 볼륨과 환경변수를 새 스택에 연결합니다. 다른 서버에서는 아래 백업·복원 절차를 사용합니다. **같은 자료를 두 앱에서 동시에 열지 마세요.**

## 백업과 복원

### master.key

`master.key`는 서버가 자동 생성하고 2단계 인증(TOTP) 비밀정보를 보호하는 내부 키입니다. 거래 DB 전체를 암호화하는 키는 아닙니다. **실행 중인 서버의 키를 삭제하거나 교체하지 마세요.** 기본 Docker 설치에서는 데이터 볼륨의 `/data/master.key`, 사용자 지정 설치에서는 데이터 폴더에 있습니다.

**새 `.zip.age` 백업은 복원용 키까지 포함해 파일 전체를 암호화합니다. 별도 키 파일 없이 백업 파일과 백업 비밀번호로 복원합니다.** 기존 `.zip` 백업은 여전히 원래 `master.key`가 필요합니다. 기존 백업을 보관하는 동안 원래 키도 보관하세요.

기존 ZIP용 키는 **백업과 복원 → 기존 ZIP 백업용 키 파일 → 키 파일 다운로드**에서 관리자 비밀번호와 필요한 경우 인증 코드를 입력해 내려받습니다. 웹에 접속할 수 없다면 별도의 비공개 폴더로 복사할 수 있습니다. 기존 사본을 덮어쓰지 마세요.

```bash
mkdir -p private-backup
chmod 700 private-backup
docker cp duet-ledger:/data/master.key ./private-backup/master.key
chmod 600 ./private-backup/master.key
```

### 백업 만들기

1. 관리자 메뉴 → **백업과 복원**을 엽니다.
2. 처음에는 **새 백업 비밀번호**와 확인란에 12자 이상의 비밀번호를 입력하고, 현재 관리자 비밀번호·필요한 인증 코드로 저장합니다. 256바이트까지 지원합니다.
3. 백업 비밀번호를 1Password 같은 안전한 곳에 보관합니다. 잃어버리면 새 서버에서 복원할 수 없습니다.
4. **백업 만들고 다운로드**를 누릅니다. 검증한 `.zip.age` 파일이 서버에 저장되고 장치로 내려받아집니다.

모든 사용자의 자료·영수증·공통 디자인·2단계 인증 복원용 키가 암호화됩니다. 서버는 자동 백업을 위해 백업 비밀번호를 내부 키로 암호화해 보관합니다. 비밀번호를 설정하기 전에는 수동·자동 백업을 생성하지 않습니다. 비밀번호 변경은 이후 백업에만 적용되며 **기존 백업에는 당시 비밀번호가 필요합니다.** 서버 접근 권한이 있는 사람에게는 이 암호화가 접근 차단을 제공하지 않습니다.

설정 후 서버 실행 중 하루마다 자동 백업합니다. 자동 정리 시 수동·복원 직전 생성분을 포함한 최근 7개를 남깁니다. 중요한 파일은 다른 장치에도 내려받으세요. JSON·CSV 내보내기는 서버 백업을 대신하지 않습니다.

**복원 전에 각 기기의 전송 대기 기록을 동기화하거나 내보내세요.** 서버 백업에는 기기의 대기 자료가 포함되지 않습니다. [오프라인 안내](offline.md)

### 화면에서 복원하기

**모든 사용자의 자료가 백업 시점으로 바뀝니다.** 함께 사용하는 사람에게 알리고 다른 작업을 마무리하세요.

1. 현재 서버의 백업 비밀번호를 먼저 설정합니다. 복원 직전 안전 백업에 사용됩니다.
2. **복원** 탭에서 저장된 백업을 고르거나 장치의 `.zip.age` 파일을 첨부합니다.
3. 해당 백업을 만들 때 사용한 **백업 비밀번호**를 입력합니다. 기존 ZIP이라면 비밀번호 대신 **기존 ZIP 백업의 원래 키 파일**을 펼쳐 키를 첨부합니다. 같은 서버의 기존 ZIP은 현재 키를 자동 사용합니다.
4. **백업 확인하기**를 눌러 시점과 사용자·계좌·거래·영수증 수를 확인합니다.
5. 현재 관리자 비밀번호·필요한 인증 코드로 재인증하고 명시 확인 후 **현재 자료 백업 후 복원**을 누릅니다.
6. 백업에 들어 있던 계정으로 다시 로그인해 잔액·거래·사진·공유 권한을 확인합니다.

암호화 파일의 인증·DB 무결성·사진을 먼저 검사합니다. 비밀번호 오류나 파일 손상 시 복원하지 않습니다. 복원 직전에는 현재 서버의 백업 비밀번호로 암호화한 안전 백업을 생성하며, 생성이나 DB 반영이 실패하면 기존 자료를 유지합니다. 되돌리려면 **복원 직전 자동 백업**을 선택하고 그때 사용한 비밀번호로 같은 절차를 진행하세요.

복원은 **모든 로그인 세션·대기 초대·API 앱 비밀번호를 무효화**합니다. 계정·승인된 공유 관계·TOTP 비밀정보·복구 코드는 보존됩니다. 기존 인증 앱을 그대로 사용할 수 있습니다. 웹 복원은 현재 서버의 내부 키와 자동 백업 비밀번호를 유지하고, 복원한 TOTP 정보를 현재 키로 다시 보호합니다.

웹 업로드는 **512MB**, 압축 해제 자료는 **10GB**까지 지원합니다. 프록시 제한·디스크 여유·전송 시간 제한이 먼저 적용될 수 있습니다. 미리보기는 10분 동안 유효하고 재시작하면 다시 확인해야 합니다. 백업 생성·검증·복원 중 다른 요청이 잠시 대기할 수 있습니다.

### 화면을 사용할 수 없거나 대용량 백업인 경우

`restore` 명령은 기존 자료를 덮어쓰지 않고 새 폴더에 복원합니다. 새 백업은 `--password-file`로 비밀번호 파일을 지정하거나 `--password-file -`로 표준 입력에서 읽습니다. 비밀번호를 명령 인수나 셸 이력에 직접 넣지 마세요. 파일의 마지막 줄바꿈 하나는 제거합니다.

### 별도 Docker 볼륨으로 시험 복원

`private-backup`에 백업 파일과 `password.txt`를 준비합니다. 비밀번호 파일은 본인만 읽도록 권한을 제한하고 복원 후 안전하게 관리하세요. 아래 `BACKUP.zip.age`와 `IMAGE`를 실제 파일명과 호환 앱 이미지로 바꾸세요. 기존 운영 볼륨은 유지합니다.

```bash
docker volume create duet-ledger-restore-test
docker run --rm --user 0 \
  -v duet-ledger-restore-test:/restore \
  -v "$PWD/private-backup:/backup:ro,Z" \
  --entrypoint sh IMAGE -c \
  '/duet-ledger restore --archive /backup/BACKUP.zip.age --password-file /backup/password.txt --data-dir /restore/restored && chown -R 10001:10001 /restore/restored'
```

새 백업의 명령행 복원은 내부 키를 새로 생성하고 TOTP를 다시 보호합니다. 이후 자동 백업에도 복원에 사용한 비밀번호가 적용됩니다. 기존 `.zip` 복원은 `--archive /backup/BACKUP.zip --key-file /backup/master.key`를 사용하며, 복원 후 웹에서 백업 비밀번호를 설정하세요. `:Z`는 SELinux 환경용입니다. 복원용 사본만 있는 전용 폴더를 사용하세요.

서버 내부에서만 열리는 별도 포트로 확인합니다.

```bash
docker run -d --name duet-ledger-restore-check \
  -p 127.0.0.1:18089:8080 \
  -e DUET_LEDGER_DATA_DIR=/data/restored \
  -v duet-ledger-restore-test:/data IMAGE
```

`http://localhost:18089`에서 다시 로그인해 거래 수·잔액·사진·공유 권한을 확인합니다. 복원하면 기존 로그인 세션·대기 초대·앱 비밀번호는 무효화됩니다. 계정과 기존 공유 관계 자체는 보존되므로 외부 공개 전 확인하세요.

실제 전환 시에는 시험 컨테이너를 중지한 뒤, 본래 `compose.yaml`에서 데이터 볼륨의 `name`을 `duet-ledger-restore-test`, `DUET_LEDGER_DATA_DIR`을 `/data/restored`로 변경하고 기존 서비스를 재생성합니다. **같은 볼륨을 두 서버에서 동시에 열지 마세요.** 이전 볼륨은 검증이 끝날 때까지 보존합니다.

### 로그인 비밀번호 복구

서버 관리 권한이 있고 로그인이 불가능할 때만 사용합니다. 계정 아이디를 확인하고 기존 앱을 중지합니다. 새 비밀번호는 8자 이상이어야 합니다.

```bash
docker compose stop duet-ledger
read -rsp '새 비밀번호: ' duet_new_password
printf '\n'
printf '%s' "$duet_new_password" | docker compose run --rm --no-deps -T \
  duet-ledger reset-password --username 실제아이디
unset duet_new_password
docker compose up -d
```

인증 앱·복구 코드도 잃었다면 `reset-password`에 `--disable-totp`를 추가할 수 있습니다. **이 작업은 해당 계정의 모든 세션과 앱 비밀번호를 폐기합니다.** 복구 후 2단계 인증과 연결 키를 다시 설정하세요.
